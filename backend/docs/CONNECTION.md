## 1. What I need from you

### 1.1 Cloudflare (2 values)

| Key | Where to get it | Used for | Needed by |
|-----|-----------------|----------|-----------|
| `CLOUDFLARE_ACCOUNT_ID` | Dashboard → any Worker → right sidebar → **Account ID** | Every API call | Immediately |
| `CLOUDFLARE_API_TOKEN` | Dashboard → My Profile → **API Tokens** → Create → template **"Edit Cloudflare Workers"** | Creating D1/KV/R2, setting secrets, deploying | Immediately |

**Exact scopes the token needs:**

| Permission | Access | Why |
|------------|--------|-----|

| User → User Details | Read | Verify the token owner |

> The same token goes into **GitHub → Settings → Secrets** as `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` so CI can deploy automatically.

## 2. Where the keys live (the "safe place in Cloudflare")

Two separate stores, deliberately split:

### 2.1 Real secrets → **Workers Secrets** (encrypted at rest)

```
Cloudflare Dashboard → Workers & Pages → sande-backend-dev → Settings → Variables and Secrets
```

| Name | Type | Source |
|------|------|--------|
| `GOOGLE_CLIENT_ID` | Secret | Your Google Web client ID |
| `GOOGLE_CLIENT_SECRET` | Secret | Your Google Web client secret |
| `JWT_SECRET` | Secret | Generated |
| `ENCRYPTION_KEY` | Secret | Generated |
| `ADMIN_API_KEY` | Secret | Generated |

These are **write-only from the API** — after setting them, Cloudflare never shows the value again. That is the correct "safe place": you cannot leak what you cannot read.

### 2.2 Connection manifest → **KV namespace `sande-config`** (readable)

Contains **identifiers only, never credentials**:

```json
{
  "project": "sande-2-online",
  "environment": "dev",
  "cloudflare": {
    "accountId": "…",
    "worker": { "name": "sande-backend-dev", "url": "https://…workers.dev" },
    "d1": { "name": "sande-platform-dev", "databaseId": "…" },
    "kv": { "session": {…}, "rateLimit": {…}, "config": {…} },
    "r2": { "backups": { "name": "sande-backups-dev" } }
  },
  "google": {
    "projectId": "…",
    "oauthClientId": "…",
    "oauthClientSecretLocation": "workers-secret:GOOGLE_CLIENT_SECRET",
    "androidPackageName": "com.example.sande",
    "androidDebugSha1": "B6:A8:…"
  },
  "secretsLocation": "workers-secret (encrypted at rest, not readable via API)"
}
```

Purpose: any later tool, CI job, or future session can discover the entire wiring from one KV read instead of asking you for IDs again.

### 2.3 Your own copy (recommended)

The manifest is also safe to keep in your password manager or a private repo. It contains no secrets — only IDs.

## 3. Commands, in order

```bash
cd sande-2-online/backend

# 0. One-time: install deps
npm install

# 1. Create Cloudflare resources + write IDs into wrangler.toml
CLOUDFLARE_API_TOKEN=xxx CLOUDFLARE_ACCOUNT_ID=xxx \
  node scripts/cloudflare-setup.mjs --env=dev

# 2. Apply D1 schema (29 tables)
CLOUDFLARE_API_TOKEN=xxx CLOUDFLARE_ACCOUNT_ID=xxx \
  node scripts/d1-migrate.mjs --env=dev

# 3. Set secrets (add --generate the first time)
CLOUDFLARE_API_TOKEN=xxx CLOUDFLARE_ACCOUNT_ID=xxx \
  GOOGLE_CLIENT_ID=xxx GOOGLE_CLIENT_SECRET=xxx \
  node scripts/set-secrets.mjs --env=dev --generate

# 4. Deploy the Worker
CLOUDFLARE_API_TOKEN=xxx CLOUDFLARE_ACCOUNT_ID=xxx \
  node scripts/deploy-worker.mjs --env=dev

# 5. Store the connection manifest in KV
CLOUDFLARE_API_TOKEN=xxx CLOUDFLARE_ACCOUNT_ID=xxx \
  GOOGLE_CLOUD_PROJECT_ID=xxx GOOGLE_CLIENT_ID=xxx \
  node scripts/store-config.mjs --env=dev

# 6. Verify everything
CLOUDFLARE_API_TOKEN=xxx CLOUDFLARE_ACCOUNT_ID=xxx \
  node scripts/verify-connection.mjs --env=dev
```

## 4. Why the scripts instead of `wrangler`

`wrangler` cannot run on this Android device — its `workerd` binary has no `android-arm64` build:

```
Error: Unsupported platform: android arm64 LE
    at pkgAndSubpathForCurrentPlatform (…/workerd/lib/main.js:60:11)
```

The scripts in `backend/scripts/` do the same work through the **Cloudflare REST API**, so they run anywhere Node runs.

**CI is unaffected** — GitHub Actions runs on Linux and uses `cloudflare/wrangler-action@v3`, which works normally. See `.github/workflows/ci.yml`.

## 5. GitHub secrets needed for automatic deploys

Repo → Settings → Secrets and variables → Actions → New repository secret:

| Secret name | Value |
|-------------|-------|
| `CLOUDFLARE_API_TOKEN` | same token as above |
| `CLOUDFLARE_ACCOUNT_ID` | same account ID as above |

Once these exist, every push to `main` builds the APK, runs the Android tests, typechecks and tests the backend, and deploys the Worker to staging automatically.
